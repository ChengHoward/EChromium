# EChromium 现代浏览器重构规划

日期：2026年11月7日。状态：规划草案，已完成一轮功能遗漏复核。首发平台建议为 Windows x64，优先适配 Windows 11；其它平台与架构在内核产物和功能验收后进入支持范围。

目标是建设可长期日常使用的桌面浏览器，覆盖主流浏览器的主要功能与交互细节。以 Navora 已有浏览器实现作为主要技术参考，结合旧项目的功能意图，建立适合独立浏览器的窗口、网页、数据和安全边界。保留旧版入口作为参照，新版使用独立入口、独立用户数据目录和开发配置，迁移通过后再切换默认入口。

“接近完整”以功能目录、真实网站兼容性和验收场景衡量。Chromium 的网页能力、Electron 暴露的宿主能力、Chrome 产品功能分别核对，不能因为内嵌 Chromium 就把 Chrome 的账号同步、扩展商店、密码管理和 DRM 视为现成功能。

## 产品范围和交付原则

1. 默认提供完整的常规浏览体验：窗口与标签、地址搜索、导航、书签历史、下载、网站权限、个人资料、设置和恢复。
2. 纳入高级体验：标签组与垂直标签、分屏、阅读模式、翻译、密码自动填充、扩展、网页应用、资源管理和同步。
3. 先交付稳定的本地浏览器，再引入账号与服务器。云同步、翻译服务、信誉服务等必须有独立的数据流和启用方式。
4. 每个功能都覆盖入口、状态、取消、失败、恢复、键盘与无障碍；只有按钮或菜单项不算完成。
5. 能力状态统一使用：待设计、待内核核验、可开发、开发中、待验收、已验收、受限支持。规划中的能力均未据此标记为已实现。
6. 定制内核经能力适配层接入；新增底层补丁单独列任务、维护类型与回归用例，并记录对应二进制，不把全部修改累积到应用层。

## 已确认的参考和需要核验的边界

### 本地参考

- 旧项目：`app.js` 管理窗口、下载、存储、启动参数和协议；`app/index.js` 通过 jQuery 与 webview 管理标签和网页操作。
- Navora：`D:\electron\navora-harness\navora-desktop`。其 package.json 和已安装包清单均声明 `45.0.0-desktop.2`；本规划未运行该二进制，声明版本不是能力验收。
- Navora 的 `shared/appearance.ts` 提供雾蓝、鼠尾草绿、淡藤紫、暖砂、柔杏、石墨六种色系以及亮暗配色。
- `electron/modules/window-material.ts`、`shared/window-material.ts`、`src/styles/window-material.css` 展示 Acrylic 请求、半透明宿主表面、系统环境判定和实色回退。
- `electron/modules/window-chrome.ts` 使用 Windows 原生 frame、隐藏标题栏与 titleBarOverlay。优先保留系统窗口按钮、缩放与贴靠行为。

- Navora 仓库 LICENSE 为 MIT。实际复用代码时保留相应版权和许可；其 vendor、图标、字体和其它第三方资源分别检查。

### 第一阶段必须回答的能力问题

- 确定发行版本、二进制路径、文件摘要、实际 Electron/Chromium/Node 版本、配套类型和平台，固定为可复现的运行时清单。
- 验证 WebContentsView 的显示隐藏、尺寸、关闭、跨窗迁移、圆角、焦点、输入法及弹层遮挡；跨窗迁移不能只验证静态页面。
- 验证 Acrylic、原生窗口按钮、贴靠菜单、DPI 坐标换算、网站信息与证书查看器。
- 原生 NativePanel 是否可用、适合哪些控件；复杂地址建议列表和 HTML 面板采用独立宿主 View 等方案时，核对焦点、层级和资源成本。
- 验证 PDF、打印、媒体编解码、WebRTC、屏幕共享、WebAuthn、客户端证书、下载中断续传和代理认证。
- 列出目标扩展及所需 API，实际测试内容脚本、后台、工具栏弹出页、权限、下载与网络规则；“能加载”不等于“可用”。
- 检查定制补丁对普通浏览兼容性、更新和安全隔离的影响。高级自动化及身份覆盖能力默认不启用，独立于常规浏览入口。
- 验证带 POST 请求体的新窗口、命名窗口、opener、关闭前确认、原生与自定义 JavaScript 对话框、导航历史恢复和滚动恢复。不能将所有新窗口简单转换为一次 loadURL。
- 验证内部协议和各 session 的注册边界、DevTools 对象绑定、站点存储与 Service Worker 清理、休眠唤醒后的连接与授权状态。

上游 Electron 只实现部分 Chrome 扩展 API，并不以兼容所有商店扩展为目标。定制版的额外兼容范围要以测试清单证明。[扩展支持说明](https://www.electronjs.org/docs/latest/api/extensions)

## Navora 浏览器参考与迁移路径

参考根目录为 `D:\electron\navora-harness\navora-desktop`。以下结论来自源码阅读，表明可参考的实现和适配点；不代表本项目已经迁入或通过了这些功能的运行验收。

### 优先参考的现有实现

- **网页容器与窗口所有权**：`electron/modules/browser-host.ts` 的 BrowserPage 和 BrowserHostManager 已分离页面与宿主窗口，使用 WebContentsView、独立布局代次和跨窗转移。迁移其身份、布局与销毁思路，将 chatId、文件混合标签和 Agent 所有权改为独立浏览器的 Profile 与工作区模型。
- **标签命令与跨窗回滚**：`electron/modules/browser-tabs-service.ts` 已包含固定、静音、复制、排序、多选、重开关闭标签，以及转移失败回滚。优先参考命令结果、目标校验与回滚机制，去掉对聊天存在性和自动化锁的硬依赖。
- **共享类型与快捷键**：`shared/browser-workspace.ts` 包含标签命令、稳定排序、关闭后相邻选择、错误提示和快捷键解析。迁移浏览器领域相关类型与规则，并按独立产品调整快捷键、资料隔离和验证样例。
- **地址栏与新标签页**：`src/components/BrowserAddressBar.vue`、`BrowserStartPage.vue`、`shared/browser-start.ts` 和 `electron/modules/browser-start-store.ts` 已提供地址输入、历史建议、常用链接与访问记录的实现路径。扩展为书签、已开标签、多搜索引擎、站点身份显示和更大规模历史索引。
- **标签界面与操作控制**：`BrowserTabStrip.vue`、`BrowserTabList.vue`、`BrowserTabContextMenu.vue`、`useBrowserTabController.ts`、`useBrowserTabActions.ts` 和 `useBrowserDrag.ts` 可作为布局与交互参考；浏览器界面不需要先创建一段聊天才能使用。
- **右键菜单与页面操作**：`electron/modules/browser-page-context-menu.ts` 已处理编辑目标、选区、链接、检查元素和页面变化后的回调校验。`browser-workspace-ipc.ts`、`browser-page-address.ts` 和 `browser-page-zoom.ts` 提供导航、编辑、地址动作与缩放的参考边界。
- **布局与浮层**：`useBrowserSurfaceLayout.ts`、`shared/browser-overlay-frame.ts`、`browser-popup-placement.ts` 和 `browser-native-panels.ts` 可参考原生 View 的尺寸、覆盖、锚点和陈旧请求处理。结合目标内核验证复杂浮层与焦点，不能只迁移 CSS。
- **会话快照与迁移**：`browser-session-persistence.ts` 已有版本化文件、备份、暂存提交及失败回滚；`browser-registry.ts` 使用 navigationHistory 快照与恢复。复用可验证的迁移规则，在本项目补全独立 Profile、隐私模式及存储规模要求。
- **下载状态与界面**：`browser-download-list.ts`、`browser-download-access.ts`、`shared/browser-download-status.ts`、`browser-download-presentation.ts` 和 `BrowserDownloadsMenu.vue` 可参考状态、操作可用性和展示方式；本项目需要另建持久下载记录与续传模型。
- **窗口材质与全屏**：沿用前述 appearance、window-material、window-chrome 的设计，同时参考 `window-fullscreen.ts`、`window-startup.ts` 与 `window-placement.ts` 的生命周期和位置修正。
- **现有测试样例**：优先迁移 shared 目录的排序、布局、地址、下载展示和弹层测试，以及 session-persistence、navigation-control 等领域测试。测试与运行时前提一并审查，不能把 Navora 的历史测试结果作为新项目验收。

### 迁移时必须改变的产品假设

1. **聊天归属与个人资料分开**：Navora 的多处服务以 chatId、WorkspaceFiles 和 Agent 操作所有权组织。独立浏览器以 profileId、windowId、tabId 为主，不将聊天许可直接变成网站授权。
2. **重新建立网站权限模型**：`browser-registry.ts` 的会话权限处理主要放行符合条件的全屏，将定位路由到 PermissionGate，其它权限默认拒绝。`permission-gate.ts` 本身面向 Agent 工具。通用浏览器需增加摄像头、麦克风、共享等能力，并按请求来源、顶层来源、文档与资料保存决定。
3. **沙箱与 preload 依赖核验**：当前网页创建配置为 contextIsolation 开、nodeIntegration 关、sandbox 关，并有 browser-channel-preload。迁移前列出 preload 能力，恢复远程网页沙箱基线，删除不必要的工具通道；确需内核调整时先形成依赖任务。
4. **弹窗保留网页语义**：当前 installWindowOpenHandler 创建自有标签并 loadURL，随后拒绝默认窗口创建；该路径未转交 postBody、referrer 或真实 WindowProxy 关系。OAuth、支付和命名窗口必须做专项验证，必要时修改定制内核的 View 弹窗承载接口，不能把它当成完整弹窗实现。
5. **下载与数据生命周期补全**：BrowserDownloadList 明确只保存在内存，不跨重启持久化；下载权限和目录亦带有聊天工具语义。本项目补上下载位置、另存为、历史、恢复和隐私模式分支。
6. **后台与对话框策略调整**：BrowserPage 当前主动关闭后台节流，适合其自动化需求；普通浏览器采用受保护的节能与休眠策略。js-dialog-host 的自动化默认决策不作为普通用户对话框行为，保留交互确认、来源与取消。
7. **浏览器扩展与 Navora 插件分开**：Navora 的插件市场、SDK 和 Agent 通道不等于 Chrome 扩展宿主；仍需逐项实现和验证 EXT 目录。
8. **控制迁移范围**：批注、虚拟光标、网络观测、反自动化身份覆盖、工具协议与模型通信作为可选模块独立评估。首轮只引入基础浏览需要的依赖，保留第三方许可和来源记录。

### 首轮迁移顺序

先迁移独立的共享类型、排序与地址规则和测试样例；再提取 Host 与 Tabs 的最小可运行子集，接上独立 Profile 和受限 IPC；随后迁移标签条、地址栏、右键菜单与窗口材质。最后接入访问历史、会话快照和下载面板，并替换聊天权限、内存下载与工具控制逻辑。每一批都在本项目的 userData 与打包环境中验收。

## 外观和窗口体验

### 配色与材质

默认建议使用雾蓝色系，提供上述六种色系；外观支持跟随系统、浅色、深色。应用外观和网页的 prefers-color-scheme 分开控制，用户可选择网页跟随系统或另设偏好，不能修改外壳配色时顺便改变所有网页行为。

标题栏、标签条空白区使用原生 Acrylic 底材并叠加主题色。活动标签、地址输入、菜单、正文拥有可辨识的表面；真实网页保持原色与清晰度。侧栏可采用较高不透明度的主题底色，确保背景复杂时仍可读。

原生底材作用于窗口，哪些区域透明由宿主绘制决定。CSS backdrop-filter 不能作为已经模糊 WebContentsView 内容的证明；整体降低窗口 opacity 会同时影响文字，不作为实现方案。系统版本、透明偏好、对比度和渲染异常不满足条件时回退实色。Navora 当前把 Windows 11 Build 22621 及以上列为候选支持环境，最终效果须在选定运行时和目标机器上核验。

### 布局

- 默认横向标签，标签条与标题栏整合，窗口控制区保持系统行为；地址工具栏单独一行，书签栏可隐藏或仅在新标签页显示。
- 垂直标签作为后续可选布局，保留固定标签、分组和窗口按钮可达性；窄窗口有明确折叠和溢出策略。
- 侧栏承载书签、历史、下载和阅读列表，支持固定、浮动和宽度调整。浮动层与网页的原生层级在 M0 验证。
- 站点权限、网站信息、下载提醒等短时面板使用统一锚点和焦点策略；不同窗口独立维护弹层状态。
- 页面全屏和浏览器全屏分开管理。网页进入全屏后隐藏外壳、保留清楚的来源与退出提示；退出时恢复原布局。
- 定义布局尺寸和密度 token，验证 100%、125%、150%、200% DPI、多屏切换、触摸、键盘焦点和中文输入法。

### 外观验收

浅色与深色桌面、应用与系统颜色相反、窗口激活与失焦、最大化与还原、关闭系统透明、高对比度和远程桌面均可用。启动和主题切换不出现整窗黑白闪帧。按钮、拖动区、缩放边缘、系统贴靠菜单不被自绘层拦截。跨屏后弹层仍锚定正确位置，内容不落入窗口按钮区。

## 应用架构

### 技术方案建议

应用与共享协议使用 TypeScript，界面采用 Vue 3 与 Vite，优先提取和适配 Navora 的现有浏览器实现。领域服务保持普通 TypeScript，独立于界面框架。定制 Electron 的版本、安装方式和类型文件由运行时清单固定，避免只依赖一个不明确的本地目录。

主窗口使用 BrowserWindow 承载可信的浏览器界面；远程网页由主进程创建和管理 WebContentsView。官方 WebContentsView 是主进程 View，可承载独立 WebContents。[WebContentsView 文档](https://www.electronjs.org/docs/latest/api/web-contents-view)

界面通过 preload 暴露的窄接口发出命令，主进程验证来源、参数、所属窗口与标签；网页不拥有外壳接口。远程网页禁用 Node 集成、启用上下文隔离和沙箱，保留正常 Web 安全机制；浏览器外壳同样尽量不启用 Node 集成。[Electron 安全指导](https://www.electronjs.org/docs/latest/tutorial/security)

### 模块边界

- RuntimeAdapter：版本与能力探测，定制 API 适配、回退和错误分类。
- WindowService：窗口创建、位置、原生框架、材质、全屏、多屏和关闭。
- TabService：稳定标签身份、状态机、分组、顺序、跨窗所有权和资源销毁。
- NavigationService：地址解析、导航历史、弹窗与新标签策略、错误页、协议与文件打开。
- ProfileService 和 SessionService：个人资料、持久会话、隐私会话、网络与存储隔离。
- PermissionService 和 SiteInfoService：来源判定、授权、撤销、设备选择、证书与站点数据。
- DownloadService：运行任务、落盘记录、重试、恢复、文件冲突和提醒。
- BookmarkService、HistoryService、SearchService：收藏、访问记录、地址建议、索引和导入导出。
- CredentialService、AutofillService：加密凭据、填充策略、用户确认和操作系统认证。
- ExtensionService：安装来源、兼容范围、权限、启停、更新与个人资料隔离。
- UpdateService、DiagnosticsService：分发升级、崩溃恢复、性能与用户主动导出的诊断。
- DialogService、FocusCoordinator：各类提示的排队、所属文档、取消、跨窗迁移与焦点返回。
- InternalPageService、ProtocolService：可信界面、普通内部页面、错误页与远程文档的独立权限和资源访问规则。
- SiteStorageService、DeveloperToolsService：站点存储清理、配额与后台活动，网页调试及导出。
- PolicyService：后续的托管策略、设置优先级与“由组织管理”状态；不在首轮强制引入。

### 状态与数据原则

主进程持有窗口、标签、会话、下载的权威状态，界面持有输入草稿和展示状态。稳定 tabId 不依赖数组位置、DOM id 或 WebContents id；一次跨窗转移只保留一个所有者。命令携带可核验的目标身份，导航相关操作关联文档身份或修订号，过期响应不能覆盖新页面。

标签状态至少区分 creating、loading、ready、suspended、crashed、closing、closed。导航失败不必销毁标签；挂起与关闭不同；有表单、音频、录制、上传、下载或未完成操作时按策略限制挂起和迁移。

每个 Profile 使用独立数据目录、session partition 和业务数据范围。书签、历史、下载元数据、权限和设置采用 SQLite 等支持迁移的本地存储；具体驱动在 M0 依据定制运行时 ABI 和打包验证选择。Cookie 和网页存储由 Chromium session 管理，不复制成自建 JSON 数据库。

DownloadItem、WebContents 等运行对象不序列化。数据库写入采用事务；升级前备份，迁移失败停止写入并提供恢复路径。历史和会话快照做节流与原子保存。隐私会话不写入历史、恢复快照、地址学习和遥测；用户主动下载的文件仍会保留，退出时有明确说明。

session partition 是存储与会话分区，不能当成操作系统进程隔离或完整安全边界。可信外壳、内部管理页、错误页、扩展页和远程网页采用明确的权限等级；内部页面不因使用自定义 scheme 就自动获得全部系统能力。每个 session 的协议与权限处理器分别登记。

隐私模式的承诺限定为应用主动管理的数据。系统交换文件、崩溃转储、网络服务商记录、用户主动导出或保存的文件不等同于可清除的浏览历史；涉及隐私内容时限制崩溃收集和诊断。不能声称隐私窗口提供网络匿名，或保证系统磁盘完全无痕。

## 功能目录

编号用于后续任务和验收关联。P0 是任何可访问外网版本的基础条件；P1 是日常浏览完整性；P2 是高级能力；P3 是生态与服务。优先级表示发布门槛，里程碑表示实施顺序。每项最终还需要细化为用户操作和失败场景。

- WIN06 P2：可选托盘、开机启动、便携模式、实例策略、平台差异；默认关闭最后窗口后退出。

### DATA 书签历史与浏览数据

- DATA01 P1：书签栏、文件夹、拖动排序、批量操作、搜索和撤销删除。
- DATA02 P1：访问历史、日期筛选、搜索、同文档导航去重和删除。
- DATA03 P1：恢复上次会话、异常退出恢复、关闭窗口恢复、启动页和固定标签策略。

- DATA06 P2：收藏夹高级管理、离线阅读、可验证的数据备份与迁移、重复书签整理。

验收：导入可预览与去重；失败不覆盖原数据；删除与同步墓碑语义预留；隐私记录不进入任何恢复快照。

- DL01 P1：下载气泡、列表、进度、速度、预计时间、任务栏进度和完成通知。
- DL02 P1：保存位置、另存为、同名文件冲突、文件名清理、打开文件与所在目录。

- PERM01 P0：统一 permission request 与 permission check 处理，以 Profile、真实来源、请求类型和文档身份判定。

### PRIV 隐私与隔离

- PRIV01 P0：远程内容禁用 Node、启用沙箱与上下文隔离；可信外壳限制导航、CSP 和 IPC 权限。
- PRIV02 P1：隐私窗口使用非持久会话，同一隐私资料的窗口可共享临时会话，最后一个关闭后释放。
- PRIV03 P1：Cookie、第三方 Cookie、站点数据、缓存、清理和登录状态的独立控制。
- PRIV04 P2：跟踪保护、内容过滤、站点例外、兼容性恢复开关和订阅更新。
- PRIV05 P1：搜索建议、诊断、崩溃报告及外部服务的数据发送说明与开关。
- PRIV06 P2：Do Not Track、Global Privacy Control 等偏好、网络请求审计和按站点保护报告。
- PRIV07 P1：地址建议、DNS 预取、预连接、预加载和预渲染分别控制；未确认输入的敏感文本不因优化功能被发送给站点或搜索服务。
- PRIV08 P1：隐私模式说明其网络与磁盘边界，关闭时检查会话、后台 worker、扩展和导出记录；避免诊断与崩溃转储另存访问内容。

验收：隐私访问不写历史、会话、地址学习或诊断 URL；外部协议不能调用任意系统命令；网页不能借 IPC 读取凭据或控制其它资料。

- PROF06 P2：资料级代理、语言、搜索、主题和可选工作区设置。
- PROF07 P1：便携目录、跨机器迁移与操作系统密钥绑定的冲突处理；无法解密时提供重登录或可验证恢复，不伪装成资料为空。

### MEDIA 媒体与实时通信

- MEDIA01 P1：音视频、站点静音、自动播放、后台播放和媒体快捷键。
- MEDIA02 P1：摄像头、麦克风、WebRTC、设备切换、通话及屏幕共享。

- NET01 P1：系统代理、直连、手动 HTTP/SOCKS 代理、认证和 PAC。

验收：正在下载、表单未保存时不强制重启；更新失败仍能启动；公开发布前完成签名、平台约束和安全核验。

- SYNC02 P3：书签、设置、阅读列表、标签与历史的逐类同步开关。

- COMP01 P0：本地测试站点覆盖导航、重定向、弹窗、iframe、下载、权限和错误。
- COMP02 P1：登录、OAuth、支付跳转、网盘上传、富文本与常用中文网站任务测试。
- COMP03 P1：视频会议、媒体播放、PDF、打印、WebGL/WebGPU 与硬件能力矩阵。

- COMP05 P2：扩展、通行密钥、PWA、原生面板与跨窗场景的目标兼容套件。
- COMP06 P1：隐私、崩溃、升级、多屏、DPI、辅助功能和长时间运行验收。

- COMP08 P1：固定回归覆盖内存泄漏、后台弹窗、脚本对话框轰炸、锁屏唤醒、POST 弹窗和站点清理后立即重建数据等组合场景。

验收：记录浏览器任务是否成功及受限原因，不只记录页面截图或 HTTP 状态。固定本地回归与变化中的真实网站测试分开管理。

验收：调试目标关闭、崩溃或跨窗后不残留错误绑定；网站可调试不意味着网页能调用主进程或读取其它资料；DevTools 扩展另走扩展兼容验收。

### DLG 对话框与交互协调

- DLG01 P1：alert、confirm、prompt 的来源、默认值、确认取消、后台标签提示与宿主归属；使用定制处理器时保留网页语义。
- DLG02 P0：beforeunload 覆盖导航、刷新、关闭标签、关闭窗口和应用退出；用户选择留下后不能继续销毁 View。
- DLG03 P1：HTTP 认证、代理认证、客户端证书选择的排队、取消和去重，凭据不进入普通通知或日志。
- DLG04 P1：文件打开、保存、目录选择、权限提示和系统认证的模态关系，避免窗口不可操作或对话框落在屏幕外。
- DLG05 P0：脚本对话框、弹窗、下载和权限请求的频率限制与关闭入口；后台页面不能持续抢焦点。
- DLG06 P1：面板绑定 Profile、window、tab 和文档，导航与销毁使旧请求失效；多个弹层按确定的 ESC 顺序退出并恢复焦点。

验收：一个站点不能用对话框阻断所有窗口；中文输入和屏幕阅读器可用；系统关机无法继续交互时按明确策略保存数据并退出。

### ORIGIN 内部页面与来源可信边界

- ORIGIN01 P0：为设置、历史、下载、新标签页、错误页及查看源码制定路由与权限清单，远程页面不得导航进管理接口获得宿主权限。
- ORIGIN02 P0：自定义协议的路径规范化、资源允许列表、CSP、frame 限制和每 session 注册，阻止路径穿越与任意文件读取。
- ORIGIN03 P0：地址显示处理 IDN、Punycode、双向控制字符、userinfo、长域名和不透明来源；安全图标只代表已确认的真实连接状态。
- ORIGIN04 P0：file、data、blob、about、view-source 和外部协议分别定义入口与权限；错误页、归档与 PDF 不继承可信界面的 IPC。
- ORIGIN05 P1：HTTPS 优先、混合内容与证书例外在网站信息和错误页一致呈现；全屏、指针锁定与权限提示保留不可伪装的来源和退出方式。
- ORIGIN06 P0：网页标题、favicon、下载文件名、搜索建议与同步数据进入外壳时按不可信输入处理，不通过 HTML 拼接或任意图标 URL 加载扩大权限。

验收：本地恶意页面、内嵌 frame、伪造内部地址和导航竞态不能读取宿主文件、获取管理接口或冒用其它站点的授权。地址栏与权限提示不使用网页传入的标题作为身份凭证。

### STORE 站点存储与后台生命周期

- STORE01 P1：区分 Cookie、LocalStorage、IndexedDB、Cache Storage、Service Worker、文件存储和 HTTP 缓存，按资料和站点统计实际可用范围。
- STORE02 P1：清理指定来源时覆盖目标存储类型，显示完成与失败；处理打开页面、worker 和同步任务立即重建数据的竞态。
- STORE03 P1：持久存储申请、配额、磁盘压力、数据驱逐、离线损坏和用户可见错误，不无限增长或无提示删除收藏等应用数据。
- STORE04 P1：验证分区 Cookie、第三方存储访问、嵌入登录与单点登录；保护策略和例外需保持一致。
- STORE05 P2：Service Worker 的注销、更新、站点应用卸载与后台任务停止；后台通知和隐私会话退出按所属资料管理。
- STORE06 P1：提供站点存储管理与刷新状态，区分清除缓存、清除登录状态、清除授权和清除全部数据，不能把一次 API 返回成功当成全部清除。

验收：同源与跨站嵌入、多个窗口、隐私窗口和仍在运行的 worker 下核对清理效果；按照运行时可观测能力陈述结果，不承诺无法验证的逐 Cookie 时间范围删除。

### POLICY 托管策略与受控部署

- POLICY01 P3：企业或受控环境的策略格式、校验、只读来源和“由组织管理”说明。
- POLICY02 P3：URL 与扩展允许或禁止列表、代理、下载目录、更新通道、隐私模式和开发者工具开关。
- POLICY03 P3：系统策略、资料设置、同步设置与默认值的优先级，锁定原因可见，移除策略后恢复用户选择。
- POLICY04 P3：受控部署、离线安装、证书与认证环境、策略导出及无敏感数据的诊断。
- POLICY05 P3：多系统账户的数据目录权限、策略签发来源和组织退出；资料界面的本地锁定不能声称防御同一系统账户的文件访问。
- POLICY06 P3：管理员模板与兼容版本、配置回滚、错误策略隔离；家庭和公共设备模式单独立项，不自动承诺完整家长控制。

验收：网页、普通设置或同步数据不能篡改托管策略；非法策略不使浏览器无法启动；用户可辨别个人偏好与组织限制。

## 功能范围裁决与阶段门槛

功能目录覆盖基础、进阶与后续可选产品能力；条目存在不代表必须在同一版本全部上线。基础浏览、数据可靠性、输入与无障碍、权限与来源边界属于首发核心。标签工作区、凭据、阅读、媒体与目标扩展按已核验范围逐步开放。同步、托管策略、付费服务、投屏与 DRM 作为有独立条件的后续能力管理。

P0 条目必须在 M0 建立设计与探针、M1 首个外网浏览版本前完成对应验收；不能等到 M6 再补安全边界。P1 条目在公开稳定版前逐项验收或明确裁决不支持及其影响。公开发行的信誉保护方案在 M0 调研、M6 验收；在线云服务和其订阅费用不默认成立。版本声称支持扩展时，权限、更新包可信性与兼容验证必须同时完成，不因条目属于 P2 或 P3 就省略。

M0 的关键可行性结论包括：POST 弹窗与 opener 是否可正确承载、beforeunload 是否能阻止实际销毁、浮层是否覆盖网页并保持焦点、Profile 与内部协议是否正确隔离。存在缺口时形成明确内核任务，再决定上层实现方式。

每个功能在开始开发前追加：最终交付阶段、依赖条目、支持平台、是否需要内核补丁或外部服务、离线与降级行为，以及可执行的验收场景。关键流程应采用任务级验证，如“登录后支付返回原窗口”，不能只验证“弹出过一个标签”。

## 开发里程碑

### M0 工程和内核可行性

交付可复现的新版开发入口、运行时清单、类型协议、独立用户目录、最小窗口与网页 View、能力探针以及扩展等高风险功能的可行性报告。以 Navora 的 Host、Tabs、共享类型和测试样例为参考，形成最小迁移子集与依赖清单，先确认原生层级、焦点、跨窗迁移、材质和打包可行。补充内部来源与协议设计、POST 弹窗、关闭前确认、站点存储和基础 DevTools 探针。

通过条件：干净安装可启动与构建；网页无 Node 权限；外壳 IPC 拒绝越权目标；材质关闭可回退；窗口关闭后对应网页资源和监听器释放，共享进程不被误杀。明确后续需要的内核补丁、外部服务与不确定项，并对所有 P0 条目形成首轮验收设计。

### M1 基础浏览和视觉框架

交付 Navora 风格配色、原生窗口框架与 Acrylic、横向标签、地址栏、导航、新标签页、右键菜单、查找、缩放、基础下载、基本权限决策和错误页。建立命令与快捷键系统。完成 P0 来源边界、POST 弹窗语义、关闭前确认与滥用限制，提供基础网页 DevTools。

通过条件：常用网站可完成打开、搜索、导航、登录、上传和下载；输入法与焦点正常；禁止未知权限静默放行；不会因坏 URL、关闭空窗口或网页崩溃导致应用退出。全部 P0 通过固定回归，POST 回跳、取消关闭与对话框滥用不会丢失页面或阻断整个应用。

### M2 日常浏览完整性

交付标签排序、跨窗拖动与恢复、固定标签、弹窗策略、完整下载管理、网站信息与权限管理、书签、历史、清理数据、设置和无障碍基础。补全对话框与系统认证的焦点协调、站点存储管理和睡眠唤醒。多 Profile 的目录与数据隔离从 M0 奠定，在此完成基础入口。

通过条件：重启恢复、断网重试、多窗口状态同步、权限撤销和隐私窗口通过固定场景测试；资料与隐私数据不串用。

### M3 数据与效率

交付书签管理与导入导出、多资料完整体验、标签组、垂直标签、分屏、侧栏、会话管理、PDF、截图、打印与阅读列表。补齐打印预览、归档、导航历史与滚动恢复的支持范围、延迟恢复标签及开发者工具管理。完善数据备份、迁移、崩溃恢复和性能基线。

通过条件：100 标签量级的固定压力场景能够管理和恢复，不把该数量当成已测性能承诺；拖动与批量关闭无丢失；升级失败可以恢复数据。

### M4 凭据与网页高级能力

交付经过核验的密码管理与填充、通行密钥使用体验、阅读模式、翻译、朗读、媒体控制、画中画、站点应用、资源休眠与任务管理器。M0 发现的凭据或媒体内核缺口在本阶段前解决。

通过条件：跨来源填充、权限、加密存储、操作系统认证和网页动态表单测试通过；有保护条件的标签不会被错误挂起；外部服务与离线状态清楚。

### M5 扩展和兼容

交付扩展管理与工具栏、目标扩展支持清单、对应内核补丁、内容保护与站点例外、目标媒体和 PWA 兼容验证。DRM、投屏和完整商店链路按可行性结果独立交付，不以一个总开关声称全部支持。

通过条件：每个受支持扩展完成实际用户任务；权限升级有确认；扩展异常不破坏其它资料；不支持能力有准确说明。

### M6 可维护的公开发行

交付签名安装包、可信更新清单与包验证、更新通道、下载校验与回退、干净机器验证、安全与隐私核验、多屏和长时间运行测试、诊断与支持文档。验收恶意站点与下载保护方案及其受限范围。发行工程从 M0 开始，M6 完成公开分发门槛。

通过条件：基础到高级能力按实际支持范围验收，无阻断浏览、数据丢失或越权缺陷；自动更新可失败回退；安全补丁跟进与定制内核维护有明确流程。

### M7 同步和平台扩展

交付可选账号与端到端加密同步、设备管理、冲突合并和云端删除；根据内核产物扩展其它平台。托管策略和受控部署作为独立可选版本能力。AI 助手、自动化、垂直业务入口在核心体验稳定后单独评估。

通过条件：多设备离线与冲突、设备撤销、密钥恢复、旧客户端和服务不可用场景通过测试；没有服务器时本地浏览仍完整可用。

实施依赖为 M0 → M1 → M2 → M3，之后 M4、M5 可按内核能力分别推进；M6 汇总正式发行门槛，M7 不阻塞本地版本。安全、权限、测试和数据迁移贯穿全部阶段。先完成 M0 与 M1 的一次迭代，再依据实际速度估工期，不把跨越应用、内核与服务的全部范围压成短期承诺。

## 统一验收模板

每个功能任务至少记录：用户目的、入口、前置条件、所属 Profile 与窗口、主流程、取消与失败、数据读写、权限、键盘与无障碍、日志清理、资源销毁、重启恢复和测试证据。涉及内核时追加实际构建标识和平台范围。

交互组合需要单独验证：拖动中关闭源窗口、导航后收到旧权限答复、截图过程中关闭标签、下载取消与完成同时发生、跨屏同时缩放、更新时数据库迁移失败、隐私会话崩溃、断网后 OAuth 回调、多窗口修改同一书签，以及网页 beforeunload 阻止关闭。

另外覆盖：POST 表单 target=_blank、命名窗口重复使用、opener 关闭、脚本对话框连续弹出、打印取消后焦点恢复、清理站点数据时 worker 重建数据、证书例外到期、设备授权后拔除、DevTools 打开时跨窗、外壳显示恶意网页标题、隐私窗口产生崩溃转储，以及锁屏唤醒后的共享指示。

测试分三层：领域状态与数据迁移、真实 Electron 集成、本机原生交互与视觉。截图无法证明焦点、权限和进程释放；模拟 API 也无法证明原生材质、编解码器与系统认证。性能数值在指定设备、固定页面集合和构建方式下测量后建立预算。

## 第一轮具体任务

1. 建立新版入口、TypeScript 配置、构建命令、锁文件和独立开发数据目录；记录 Navora 参考版本、被提取模块及许可。
2. 记录并固定定制 Electron 包、二进制摘要、实际内核版本和类型。
3. 建立 RuntimeAdapter，输出材质、NativePanel、网站信息、跨窗迁移和扩展的能力报告。
4. 做一个原生窗口按钮、雾蓝与深色主题、Acrylic 与实色回退均可切换的最小窗口。
5. 参考 Navora 的 Host 与 Tabs 提取最小子集，使用独立 Profile 创建两个隔离的 WebContentsView，验证切换、焦点、输入法、布局和资源释放。
6. 验证地址建议浮层、权限面板、网页右键菜单在 View 之上的层级及坐标。
7. 将 Navora 的稳定身份和命令规则适配为 tabId、windowId、profileId，建立独立导航和关闭状态机，移除 chatId 与 Agent 工具的强耦合。
8. 完成地址分类、导航、新标签、弹窗路由、基础错误页和快捷键。
9. 实现默认拒绝未知权限、真实来源校验与可信界面 IPC 约束。
10. 用本地回归站点验证重定向、弹窗、文件、下载、beforeunload、崩溃和跨窗迁移，输出第一份能力与限制清单。
11. 验证 POST 新窗口、opener 与命名目标，用户选择保留页面后不得继续销毁；无法保留语义时先形成内核补丁任务。
12. 建立内部来源与协议清单、恶意标题等输入样例、对话框队列，以及站点存储清理与 DevTools 绑定探针。
