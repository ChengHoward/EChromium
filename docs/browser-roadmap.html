先验证底层，再逐步补全产品

M0 → M1 → M2 → M3；M4 与 M5 按内核能力分别推进。M6 完成公开发行门槛，M7 不阻塞本地浏览。安全、数据迁移和测试贯穿各阶段。

第一轮最小交付

  1. 固定二进制、类型和运行时摘要，建立独立开发数据目录与 Navora 最小迁移清单。
  2. 做出原生窗口按钮、雾蓝与深色主题、Acrylic 与实色回退。
  3. 参考 Navora 的 Host/Tabs，验证两个隔离网页 View 的切换、焦点、输入法、跨窗迁移和销毁。
  4. 验证地址建议、权限面板和菜单的层级与 DPI 坐标。
  5. 完成独立资料身份、导航路由、全部 P0 来源边界、关闭前确认与弹窗语义。
  6. 生成扩展、凭据、媒体及 PWA 的能力缺口清单。

先完成 M0 和 M1 的一次迭代，再根据实际速度估算后续工期。

功能目录

P0：外网浏览基础；P1：日常浏览完整性；P2：高级能力；P3：生态与服务。优先级表示发布门槛，不等同于里程碑。

Navora 风格外观

默认建议雾蓝，提供鼠尾草绿、淡藤紫、暖砂、柔杏和石墨色系；支持跟随系统、浅色和深色。

  • 标题栏和标签条空白区：原生 Acrylic 底材叠加半透明主题色。
  • 活动标签与地址输入：保持清楚的轮廓、选中和焦点。
  • 真实网页：保持清晰和原色，应用外观不强制改变网站主题。
  • 窗口控制：保留系统按钮、拖动、缩放和贴靠布局。
  • 回退：系统透明关闭、高对比度、能力不足或异常时使用实色。

背景材质请求成功不代表实际模糊可见。必须验证浅深桌面、失焦、最大化、多屏与不同 DPI。CSS 模糊不能替代对原生网页层级的验证。

建议技术结构

  1. Vue 3 + TypeScript：可信外壳界面。
  2. 受限 preload：明确的命令与事件。
  3. 主进程领域服务：窗口、标签、权限、会话和数据。
  4. WebContentsView：承载隔离的远程网页。
  5. RuntimeAdapter：定制 API、能力探测和回退。
  6. 本地业务数据库：迁移、备份和事务；网页存储继续由 Chromium session 管理。

需要提前验证的功能

完整扩展兼容、密码与通行密钥、媒体格式与 DRM、PWA 推送、云同步各有独立的内核、服务或分发条件。建立目标功能与网站清单，逐项验证，发布准确的支持范围。

每个功能的完成标准

入口、主流程、取消、失败、权限、数据读写、键盘与无障碍、日志清理、资源释放和重启恢复。涉及内核时记录二进制、平台和实际行为；按钮可点击只代表入口完成。

迁移边界

  • 聊天与 Agent 的工具权限不能直接成为网站权限；改为资料、来源和文档身份。
  • 现有网页配置关闭沙箱，需核验 preload 并恢复浏览器隔离基线。
  • 弹窗重建路径未转交 POST、referrer 和完整 opener 语义，需专项探针或内核补丁。
  • 下载列表只存内存；持久下载、恢复和隐私策略需补全。
  • 后台节流与自动对话框策略面向自动化；独立浏览器保留用户确认和节能行为。
  • Navora 插件与 Chrome 扩展分别管理，参考测试在本项目重新运行。

实施顺序

共享类型与规则 → Host/Tabs 最小子集 → 独立 Profile 与 IPC → 标签条、地址栏、菜单与材质 → 历史、快照和持久下载。
