## 2. 启动、构建和运行时

在工作区内执行：

```powershell
npm start
```

这会先构建再启动。只改前端时可用 `npm run dev`，开发服务固定为 `http://127.0.0.1:5188/`；改主进程或 preload 后须重新启动开发进程。

- Node.js 要求 `>=22.12.0`；依赖和锁文件已准备，无需每次重新安装。
- 发行包固定为定制 `45.0.0-desktop.3`，不是官方同名版本。
- 默认实际执行文件：`.local/electron/desktop-5808bd088b26/electron.exe`。
- executable SHA-256：`5808bd088b261cc0ad0506848a594a76b19a091aa3cac868c85b53db09e3d7ba`。
- 该二进制实际报告 Electron `45.0.0-beta.5`、Chromium `156.0.8078.36`、Node `24.22.0`。以摘要、清单和实际运行报告共同识别版本，不单凭 `process.versions.electron` 判断发行包。
- `runtime-lock.json` 保存锁定信息，`scripts/runtime.mjs` 校验并选择运行时。`ECHROMIUM_ELECTRON` 可显式选择其它开发构建，但会绕过默认选择逻辑。
- 普通用户资料：`.local/user-data/browser-v1.json`；网页持久 session 同属该用户目录。不要清空真实用户资料以通过测试。
- `ECHROMIUM_USER_DATA` 用于指定隔离资料。启动器会删除继承的 `ELECTRON_RUN_AS_NODE`，不要绕过这一处理。
- 桌面执行在受限代理中可能需要正常桌面权限；不能通过关闭 Electron 沙箱解决权限或启动问题。
- 用户习惯要求完成修改后重新启动预览。正常关闭已有窗口、等待保存，若有离开确认则遵守，不强制杀掉真实页面。进程编号会变化，不使用聊天中的旧 PID。

参考源码可读于 `D:\electron\main\src\electron`、Chromium `D:\electron\main\src\chrome`、Navora `D:\electron\navora-harness\navora-desktop`。本轮没有修改这些目录；应用工作区之外的改动须依据当前会话授权和文件权限处理。

## 3. 源码入口和所有权

- `src/main/index.ts`：单实例、资料位置、IPC 注册、启动恢复和退出。
- `src/main/browser.ts`：`Browser` 管理宿主窗口；`Host` 管理窗口级资料、session 和标签；`Tab` 持有状态与实际 `WebContentsView`。切换、关闭、恢复和宿主身份以主进程为准。
- `src/preload/`、`src/shared/model.ts`：可信外壳的受限通信和状态类型，不向任意网页暴露浏览器控制能力。
- `src/renderer/App.vue`、`style.css`：窗口框架、Vue 标签栏、地址栏、书签栏、内部页与网页位置。
- `src/renderer/pages/`：新标签、设置、书签、历史、下载和网站数据界面。
- `src/shared/appearance.ts`：六组基础配色、明暗模式、深浅和透明度边界、设置校验、颜色生成；`src/main/material.ts`：原生材质与更新顺序。
- `src/main/popups.ts`、`src/shared/window-open.ts`：新窗口请求分类，原生 guest 挂接成标签或保留独立弹窗。
- `src/main/tab-transfer.ts`、`tab-previews.ts`、`src/shared/window-session.ts`：实际 View 转移、内存预览、重启快照。三者不能互相替代。
- `page-find.ts`、`page-dialogs.ts`、`address-suggestions.ts`：定制 NativePanel。它们与真实网页是不同的界面层。
- `permissions.ts`、`site-data.ts`、`site-inventory.ts`、`browsing-data.ts`、`downloads.ts`：权限、站点清理与统计、浏览数据和下载生命周期。
- `tests/domain.test.ts`、`src/main/smoke*.ts`：领域和真实桌面集成检查；`src/main/ui-review.ts`：可重复截图入口。
- `src/main/ui-text-audit.ts`：仅在隔离外壳执行的静态文字颜色测量，不向用户网页注入、不等同原生控件或 DWM 的可读性认证。

当前 session 仍属于 Host，不是每标签独立。跨窗口转移要求资料、隐私域和 session 兼容。不能直接删除 session 相等条件来声称已支持同窗口多会话。

## 4. 已确定的界面契约

用户已多次纠正过以下细节，继续优化时必须保留：

1. 左上角是“标签总览”，不是品牌或切换主题按钮。点开将当前窗口标签平铺选择；首个标签紧贴按钮。
2. 标签激活和悬停采用同一顶部圆角及底部外扩反向圆角，但悬停只有约 45% 底色强度。未激活、未悬停的标签不铺底色；分隔线在高亮标签两侧隐藏，鼠标在覆盖区域仍命中标签。
3. 总览和新建按钮图标与标签图标垂直对齐。进入动效从下向上，离开向下并压缩宽度；固定、压缩和减少动态效果均有处理。
4. 标签最小宽度 40px，固定 42px，普通当前标签至少 112px；数量增加后逐级压缩并可横向滚动。不要恢复旧的 90px 强制最小宽度。
5. 标签图标／加载指示为 16px；标题为 12.5px、20px 行高，当前字重 500；关闭按钮命中区域 22px。压缩标签悬停时文字在关闭按钮前渐隐。
6. 标题栏透色最强，标签／工具栏／书签栏较弱，地址输入框更稳。View、内部页面保持实色；不要重新把所有区域调成同等透明，或让额外底色叠加成完全不透。
7. `transparency` 限定整数 15–75，默认 72；`themeDepth` 限定整数 0–100，默认 50，两个滑块松开后保存。深浅在实色模式也可调；透明度在实色回退时停用并保留选择。
8. 自动／浅色／深色放在菜单与外观设置；自动响应系统，显式选择不被系统通知覆盖。按钮悬停保持普通箭头光标。
9. 设置滚动条贴内容区最右侧，正文单独限宽 788px，侧栏固定。原生 View 外框仍保留既定 7px 留白和 10px 圆角。
10. 浏览器操作区和书签栏不能意外选中文字；地址编辑、普通文本输入与内部说明仍可选择，网页的选择行为不受外壳 CSS 影响。

新的颜色层次使用基础 `shell/sidebar/surface/header/ink/muted/accent/stroke/selection`，再生成 `bar-surface/field-surface`、`on-accent` 和三个 chrome 透明色。CSS 中 `--hairline`、`--hover` 必须在 `.browser-shell` 的实际配色作用域计算；只在 `:root` 定义引用其它变量的派生色，会让暗色界面继承已算好的浅色边框。

六种主题继续是雾蓝、鼠尾草绿、淡藤紫、暖砂、柔杏和石墨；不得为了展示新设计而重置用户已选主题、明暗模式、深浅或透明度。不要通过降低文字整体 opacity 实现层次；用经过对比校正的 ink／muted／accent。主要按钮使用 on-accent，不使用 surface 冒充前景。标签文字色即时跟随主题底色，避免文字过渡落后底色造成瞬时低对比；原有标签形状淡入和进出动效继续保留。

## 5. 不应退回的实现细节

### 网页、通信和上下文

- 外壳和网页均保持 `sandbox:true`、`contextIsolation:true`、`nodeIntegration:false`。网页没有外壳 preload 和 `window.browser`。
- IPC 核验当前宿主、可信地址和主 frame；允许可信界面的 fragment，不允许任意 `file://` 页面冒用。不能放宽校验去消除退出时的迟到 IPC 日志。
- 导航、权限、面板、数据清理及预览都有身份／代数／令牌检查。异步结果必须再次验证归属，防止导航后或跨窗口转移后执行旧动作。
- 已销毁 View 的 `webContents` 可能不可再读取；需要先保留局部引用并检查 `isDestroyed()`。

### 新开页面和跨窗移动

- 普通 `target=_blank`、无弹窗参数的 `window.open` 和新窗口表单进入浏览器标签；Ctrl／中键的 background disposition 保留前台页。
- 必须在原生 `createWindow` 回调中采用 `options.webContents`，再交给 `Browser.adoptTab`；不要拒绝后 `loadURL(details.url)`，否则丢失 POST、referrer、opener、命名目标等语义。
- 该运行时回调确实带 guest 字段，公开 TS 声明却漏写了它，代码有局部类型补充；不能据类型缺失改成新建 WebContents。
- 普通新标签使用 `outlivesOpener:true`；来源导航／关闭不应带走它。明确 popup、尺寸或 new-window 请求继续是带原生菜单的独立窗口。
- 转移必须移动同一 View，失败回滚所有权、列表、激活和原生挂接。不要通过重开网址模拟移动。

### 原生材质与面板

- 原生 `setBackgroundMaterial('none')` 在本构建会自动把清屏色置白。现有切换先在外壳绘制实色保护，再切原生材质、恢复清屏色、发布配色并撤掉保护。更新队列读取最新偏好。
- 相同材质、清屏色和窗口按钮配色有缓存；透明度或无关设置更新不应反复触发原生材质重置。隐藏构造窗口首次显示后只重申一次材质。
- NativePanel 的查找、地址建议和脚本对话框用于覆盖实际网页；普通 HTML 层不能假定会画在 WebContentsView 上方。
- 查找的结果、配色和位置更新不回写原生输入值，避免覆盖草稿及输入法；再次打开建立正确输入会话。
- 网页对话框默认的 5 秒自动同意已禁用，应用自身超时取消。不要恢复运行时默认自动接受行为。
- `beforeunload` 取消后要等渲染器恢复再完成取消；用户确认离开后才销毁。现有时序有真实回归，不能仅以简化代码为由改掉。

### 保存和退出

- 普通窗口保存版本化快照，隐私窗口不写访问历史／恢复列表；重启时只加载活动网页。
- 运行期间重开关闭标签和跨进程恢复是不同能力。重启恢复不恢复表单、完整 pageState、POST 或滚动位置。
- `flushForExit()` 保存后冻结快照，避免逐个销毁窗口的回调把完整快照缩成最后一个窗口。
- `.local/`、`test-results/` 和 `dist/` 都是本机生成数据，不应提交用户资料或把临时截图当作源资产。

## 7. 已知问题与待实现内容

### 首要调查：连续进程启动偶发超时

此前多次出现：32 项浏览回归完成，恢复的前三阶段通过，最后 disabled 进程在 90 秒内没有结束；使用同一测试资料单独重试该阶段会通过。根因未定位，不能因为重试成功就宣称问题已修复。

接手时记录进程阶段、启动／ready／创建窗口／退出等时间点，以及 GPU、单实例锁和资料锁状态，优先区分运行时启动阻塞与应用异步等待。不要靠延长超时、循环重试隐藏失败，或用删除用户资料、关闭沙箱等方式绕过。临时重试也应保留原始失败及重试证据。

### 应用功能仍有明确边界

- 当前网页标签使用通用图标，未实现完整网站 favicon 获取与安全缓存。
- 暂无完整资料管理、逐标签多 session、标签组、垂直标签、分屏、拖出桌面建窗及原生悬停卡。
- 网站数据来源枚举、存储用量类别、第三方分区 Cookie 等有范围，详见实现状态；0 B 不是“没有数据”。
- 站点信誉、打印／PDF、设备和屏幕共享选择、密码、扩展、PWA、同步、签名安装包和自动更新仍需规划实现。
- 下载没有重启续传；隐私与普通数据必须继续隔离。
- NativePanel 的真实中文输入法、读屏、多显示器 DPI、系统高对比度／减少透明度还需人工专项验收。当前可读性数值以实色调色基底计算，不等同所有壁纸下 Acrylic 的实际对比。

2. 如果继续界面工作，优先网站 favicon、标签状态可辨识性、设置窄屏与键盘可达性；用可重复截图入口复核，保持已确定的圆角和透明契约。
3. 如果接原生标签／多会话内核方案，先做能力查询与最小原型、记录实际二进制摘要，再扩展 Host/Tab 上下文模型。不能假设设计文档中的 API 已存在。
4. 按完整浏览器规划选择一个可验证闭环，更新实现状态和本交接文档，避免同时摊开多个只有界面的未接通功能。

可给新智能体的开场指令：

> 在 D:\Projects\EChromium 继续开发。先读 docs/agent-handoff.md、docs/implementation-status.md 和 README，保留现有未提交／未跟踪内容。以当前源码和最新报告为事实，遵守其中的界面契约和沙箱／身份校验；在独立资料中验证，完成后正常重启预览并更新交接记录。
